# 制度枠の自動記録（自動ログイン）

2026-11-07 追加。JALオンライン（法人・ＬＴ００）の制度枠を、MacのChrome拡張が
決まった時刻に **ログイン → 企業ＬＴ００を選択 → 70区間を記録 → ログアウト** する。

ログインしっぱなしのタブに頼る方式（無操作で約1時間で切れる）は、本人判断で不採用。

## 構成

| 部品 | 場所 | 役割 |
|---|---|---|
| 拡張 | `extension/background.js`（「自動ログイン」の節） | 定時実行・ログイン操作・ブレーカー・ログアウト |
| 設定画面 | `extension/options.html` / `options.js` | 有効化・状態表示・「いま1回だけ試す」・停止の解除 |
| 補助プログラム | `native-host/host.py`（Native Messaging） | キーチェーンから番号とパスワードを読む／Macに通知 |
| 登録スクリプト | `native-host/install.sh` | 補助プログラムを `~/Library/Application Support/jal-autologin/` に置き、Chromeに登録 |
| パスワード | macOS キーチェーン（サービス名 `jal-online-autologin`） | **拡張・リポジトリ・ログのどこにも書かない** |

拡張IDは `manifest.json` の `key` から決まる `mlffhdcicmoieohlbgpiikbgdbmknnmj`。
補助プログラムはこの拡張からしか呼べない（`allowed_origins`）。

## 初回の設定（本人が行う）

1. 補助プログラムを登録する（2026-11-07 にこのMacでは実行済み。再実行しても害はない）
   ```bash
   ./native-host/install.sh
   ```
2. ログイン情報をキーチェーンに入れる（パスワードは画面に出ず、2回聞かれる）
   ```bash
   security add-generic-password -s jal-online-autologin -a お得意様番号 -w
   ```
   パスワードを変えたときは、`-U` を付けて同じコマンドを実行すると上書きできる。
3. `chrome://extensions` で「JAL国内線 本日の空席 コレクタ」を**再読み込み**
   （権限 `nativeMessaging` を足したため必須）
4. 拡張の設定画面で「キーチェーン: 登録あり」と出ることを確認
5. **「いま1回だけ試す」**を押し、前面に開くウィンドウでログイン〜記録〜ログアウトを見届ける
6. うまくいったら「決まった時刻に自動でログインして制度枠を記録する」にチェック

## 動き

- 時刻: `CORP_SCHEDULE`（0:05 / 6:00 / 11:30、2026-11-07 本人指定）。空席(HND)の 7:00・12:00 とはずらしてある
- Macが寝ていて **60分以上遅れて発火した回は捨てる**（`CORP_LATE_LIMIT_MS`）。
  遅れた回が次の回とくっつくのを防ぐため。Macを定時に起こす仕組みは入れていない
- サイトの「制度枠を記録」ボタン（どの端末からでも）も、MacにログインしたJALオンラインの
  タブが無ければ自動ログインで記録する。そのため**別端末・Linuxからのボタンでも記録できる**
  （Macが起きていてChromeが動いていることが条件）
- 自分でログインした回だけログアウトする。本人が開いていたJALオンラインのタブを使った回は触らない
- ログアウトは画面の「ログアウト」を押す。見つからなければウィンドウを閉じるだけ（約1時間で切れる）

## ロック対策（変えないこと）

JALはパスワードを一定回数まちがえるとWebサイト全体をロックする。

- 1回の記録でログインを試すのは1回だけ。**再試行しない**
- **パスワードを送ったあとの失敗は、理由を問わずブレーカーを落とす**
  （`autoLoginTrip`）。落ちたら設定画面の「停止を解除する」まで二度と試さない。
  落ちたときはMacの通知センターに知らせる
- パスワードを送る前の失敗（画面が開かない・入力欄が無い・補助プログラムが動かない）は
  ブレーカーを落とさない（JALにパスワードが届いていないため）
- ワンタイムパスワードを求められたら、失敗としてブレーカーを落とす
- 1日の自動ログインは8回まで（`AUTO_LOGIN_DAILY_MAX`）。サイトの依頼ボタンは誰でも押せるため
- 予約・購入の画面には絶対に進まない（収集は検索APIを読むだけ）

## ログイン画面の作り（2026-11-07 実測）

- 入口 `booking.jal.co.jp/jl/corp-john/login/member-login-user-before-process?lang=ja`
  → `jallogin.jal.co.jp/contents/login`（React）
- 番号 `#LB_input-jmbnumber-1`（autocomplete=username）、パスワード `#LB_input-password`
  （以前の記録の `#LA_input-number-01` から変わっている）
- 「ログイン」ボタンは2つある（パスワード用とパスキー用）。パスワード欄から親をたどって
  いちばん近いものを押す（実画面で、パスワード用の1つ目が選ばれることを確認済み）
- 画像認証は無し。注意書きに「一部のお手続きでワンタイムパスワード」とある
- ログイン後 `/jl/corp-john/login/login-company-list` → `select[name=corpId]` に `G0000001` →
  `button[name=nextbutton]` → `/jl/dom-corp/john-top` で `sessionStorage.apiAuthCreds` が入る

## 実機での確認（2026-11-07）

- 「いま1回だけ試す」で、ログイン → ＬＴ００選択 → 記録（59便中52便）→ ログアウトまで成功。
  ワンタイムパスワード等の追加確認は出なかった。ログアウトは画面の「ログアウト」で通った
- 最初は試験ボタンが動かなかった。原因は2つ: ①定時記録のチェックが無いと自動ログインしない作りだった
  （試験から10分以内は許可するよう修正）②拡張アイコンの小窓で `confirm()` を出すと小窓ごと閉じる
  （2回押し方式に変更）
- 失敗時の画面の文言は未確認（時間切れで判定し、エラー表示らしき要素の文字を理由に残す）
